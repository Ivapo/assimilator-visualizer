**Missed prediction: N = 8970 → measured 8700.** Gate 1's text says the fixture FCD
runs from 0.1 s to 299.1 s. It runs from **9.1 s**, when the first vehicle spawns; there
are no rows before that. That span was never measured. So D = 290, not 299, and N = 8700.
The renderer follows §2.4; only the prediction was wrong. The correction is recorded in
the spec's Phase 1 close-out.

**Gate 2 failed first, and why.**
- The first full run (ffmpeg 9.0.2) gave 483 differing decoded frames, in runs ending
  at x264's 250-frame keyframes (4367–4499, 6173–6249, 7049–7249, 8161–8249). So a few
  source frames differed, and x264 carried each difference forward.
- A diagnostic showed the renderer itself was not deterministic. Rendering the same
  frame twice in one process sometimes gave different readbacks (6 of 1500 frames): a
  few MSAA edge pixels blended between two speed colours.
- Cause: **overlapping boxes at equal height.** Which one shows depended on submission
  order, and Bevy 0.19's opaque pass bins draws and does not keep their order stable
  between frames. Spawning boxes in `vehicle_id` order therefore did not fix the draw
  order that §2.3 relies on.
- The overlaps are real: 354 same-lane overlapping pairs in 117 of the fixture's 291
  snapshots, all at approach ends. A box frozen during its junction transit (OQ-2) is
  reached by the next vehicle. **This is an OQ-2 artefact for Phase 2 to handle.**

**Fix (approved by the user): depth order by `vehicle_id` rank.**
- Each box is lifted 0.01 m per rank in `vehicle_id` order among the vehicles of its
  frame, so the depth test decides overlaps and the higher id wins.
- Peak: 110 vehicles in one frame, so the maximum lift is 1.09 m (rank 109), under one
  box height (1.5 m).
- The camera is orthographic and looks straight down. Every material is unlit, and no
  light is spawned, so there are no shadows. The lift moves no pixel: gates 3 and 7
  measured exactly the same values before and after.
- Depth precision: `Depth32Float`, reverse-Z, orthographic, linear over near 0 to
  far 1000, camera at 500 m.
  - Box tops span 1.55–2.64 m, which is view depth 497.36–498.45 m and NDC depth
    0.50155–0.50264.
  - The f32 step there is 2⁻²⁴ ≈ 5.96e-8, which is 0.06 mm of height. So 0.01 m is
    1e-5 in depth, about 168 steps.
- Regression check `tests/gates.rs:determinism_overlap_frames`:
  - It covers every frame showing an overlap snapshot: 117 snapshots, **3510 frames**,
    each rendered twice in a row at the gate-2 settings, and requires identical
    readbacks.
  - It failed on the unfixed code (9 of 3510 frames differ) and passes with the fix
    (0 of 3510).

**Environment incident, not a gate result.** During the first gate run, a Homebrew
install of `ffmpeg-full` upgraded x265 to 4.3 and broke the `ffmpeg` 8.0.1 formula, which
could no longer load `libx265.215.dylib`. The user upgraded `ffmpeg` to 9.0.2, and every
gate that uses ffmpeg was re-run from scratch.
